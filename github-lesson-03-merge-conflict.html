git merge: CONFLICT (content). How do I fix it?

Short answer

A conflict means both branches changed the same lines and git is asking you to decide. Open the file, find the <<<<<<< ======= >>>>>>> markers, rewrite that part to the final text you want, then git add the file and git commit. To back out instead: git merge --abort.

The situation
On main you changed the last line of a shopping list to pasta. On a branch called feature, the same line became rice. You run git merge feature and git stops with a conflict. Work out why, decide, fix it.

Common mistakes with merge conflicts

  1. Committing the file with the markers still in it. The markers are not valid content; they land in your project. Always check they are gone before git add.
  2. Deleting the file to end the argument. That loses both versions. The fix is choosing the final text, not removing the question.
  3. Keeping both markers' text without reading it. Sometimes both sides belong together, sometimes not. The merge commit records whatever you leave, so read it.
  4. Running more merges while a conflict is open. git refuses and the state gets harder to read. Resolve, or git merge --abort, then continue.
  5. Blaming the tool. A conflict is git asking a human to decide between two real edits. It is normal, not corruption.

Frequently asked questions

What is a merge conflict?

Both branches changed the same lines, so git cannot pick for you. It stops mid-merge, marks both versions inside the file, and waits for you to choose the final text.

What do the markers mean?

<<<<<<< HEAD starts your branch's version, ======= separates it from the other branch's version, and >>>>>>> feature ends it. Delete the markers and keep the text you actually want.

How do I finish the merge?

Edit each conflicted file to its final text, git add the files, then git commit. That commit is the merge commit.

How do I back out instead?

git merge --abort returns everything to how it was before the merge. Your commits on both branches stay untouched.

Is a conflict a sign I broke something?

No. A conflict means two people changed the same place and git is asking a human to decide. It is a normal part of merging.

Can I keep both changes?

Yes. The final text is your choice: one side, the other side, or a mix of both, as long as the markers are gone.
