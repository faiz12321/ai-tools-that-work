How do I find which program is using a port on Windows?

Short answer

In Command Prompt, run netstat -ano | findstr /R /C:":3000 " (use your port number, with a space after it). The last column is the PID of the program using the port. Look the PID up with tasklist /FI "PID eq 1234", or in PowerShell with Get-Process -Id 1234. Stop it with taskkill /PID 1234 /F only after you have checked it is the program you expect.

Common mistakes when a port is in use

  1. Searching for :3000 and reading every line. The text :3000 also matches :30001 and similar ports. Put a space after the port, or read the Local Address column to the last colon.
  2. Reading the wrong column. In netstat -ano the PID is the last column. The number after the colon in the Local Address is the port, not the PID.
  3. Stopping a program by name. taskkill /IM node.exe /F stops every program with that name. Stop the one PID you checked.
  4. Stopping it before checking what it is. A name like node.exe can be many different apps. Look at the path and command line first.
  5. Forgetting that a program can start again. If something restarts the program, the port fills up again. Find out what starts it before you stop it again and again.

Frequently asked questions

What does "address already in use" (EADDRINUSE) mean?

Another program is already listening on that port, so a second program cannot use it. Find the owner of the port, or choose a different port for your app.

What is a PID?

A process ID: the number Windows gives each running program. It changes every time the program starts, so look it up fresh each time.

Should I use Command Prompt or PowerShell?

Both work. Get-NetTCPConnection and Get-Process are PowerShell commands. netstat, tasklist and taskkill are programs you can run from either one.

Do I need administrator rights?

Looking at ports and PIDs often does not need them. Stopping some programs, or seeing details of programs run by other users, may need an administrator window.

Is it safe to stop the program that is using the port?

Only if you know what it is. Check its name, path and command line first. Stopping the wrong program can lose unsaved work or stop something you need.

What if the port belongs to a Windows system program?

Do not stop it. Choose a different port for your app instead.
