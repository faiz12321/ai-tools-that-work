git: how do I delete a branch on GitHub? (remote branch)

Short answer

git branch -d deletes only the LOCAL branch - it never talks to the remote, so the copy on GitHub survives and your teammates still see it. Delete the remote branch with git push origin --delete <branch> (older spelling: git push origin :<branch>). If a branch was deleted on GitHub but still shows in git branch -a as remotes/origin/<branch>, that is a stale local bookmark - clear it with git fetch --prune. Prune never deletes your local branches.

If you delete a remote branch by mistake, push it again from a local copy - or rescue the commit from reflog.

Common mistakes with remote branches

  1. Thinking git branch -d cleans up GitHub. It never touches the network. The remote branch lives on - and teammates keep seeing it - until you push the deletion: git push origin --delete <branch>.
  2. Answering a stale bookmark with another delete. If a teammate already deleted the branch on GitHub, git push origin --delete errors with 'remote ref does not exist'. What you need is git fetch --prune to refresh your bookmarks.
  3. Fearing fetch --prune. It removes only remotes/origin/* bookmarks that no longer exist on the server - never your local branches. Setting fetch.prune=true makes the cleanup automatic on every fetch.
  4. Trying to delete the default or a protected branch. GitHub refuses both. Change the repository's default branch first, or lift the protection - no git command overrides it from your side.

Frequently asked questions

How do I delete a remote branch in git (on GitHub)?

Run git push origin --delete <branch>. The remote reports '- [deleted] <branch>' and git also removes your local remotes/origin/<branch> bookmark. The older spelling git push origin :<branch> does exactly the same thing.

Does git branch -d delete the branch on GitHub too?

No. git branch -d only deletes your LOCAL branch and never talks to the network. The branch on the server survives - teammates still see it - until you push the deletion with git push origin --delete <branch>.

Why does git branch -a still show remotes/origin/<branch> after it was deleted?

The remotes/origin/* lines are local bookmarks (remote-tracking refs), updated only when you fetch or push. If the branch was deleted on the server - by you or a teammate - run git fetch --prune to remove the stale bookmarks. Set fetch.prune=true to make it automatic.

Does git fetch --prune delete my local branches?

Never. Prune only removes remote-tracking bookmarks (remotes/origin/*) whose branches no longer exist on the server. Your own local branches are untouched; delete them yourself with git branch -d when done.

What is the difference between git push origin --delete and git push origin :branch?

None - they are two spellings of the same push. The colon form pushes an empty 'from' into the branch, which deletes it. --delete is the readable modern spelling; :branch is the older shorthand.
