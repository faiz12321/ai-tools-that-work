git: fatal: not a git repository. How do I fix it?

Short answer

git looks for a .git folder where you are and in every folder above you. This message means it found none: you are outside your project. Move into the project folder, for example cd myapp, and run the command again. Only run git init if you are starting a brand-new repository.

Common mistakes with not a git repository

  1. Running git init to silence the error. It creates a new empty repository around whatever folder you are in. If your project was nearby, you now have two.
  2. Assuming git is broken and reinstalling it. The message is specific: no repository found from here. It is about location, not installation.
  3. Forgetting which folder the terminal is in. Terminals stay where you left them, and a new tab can open somewhere else entirely. pwd tells you where you are.
  4. Running git inside the wrong project. Two folders with similar names both answer silently. Check with git remote -v before you push anything.
  5. Touching the .git folder by hand. Never move or rename .git to help git find it; that breaks the repository.

Frequently asked questions

What does not a git repository actually mean?

git searched the folder you are in and every folder above it for a .git directory and found none, so there is no repository for the command to work on.

How do I find where my repository is?

List the folders around you with ls, spot the project, and cd into it. git checks the folder you stand in and its parents, so standing inside the project is enough.

When is git init the right answer?

Only when you are starting a brand-new repository in the folder you are in. It creates the .git folder. If your project already exists nearby, git init just gives you a second, empty one.

Why is the exit status 128?

128 is git's exit status for a fatal error. 0 means the command worked. echo $? right after a command shows the number scripts see.

Can a folder lose its .git?

Yes: if .git was deleted, moved, or never copied over (hidden files are easy to miss). Then cloning again, or git init plus reconnecting the remote, is the way back.

Does this hit other git commands too?

Yes. log, add, commit and push all need a repository and fail the same way when you run them outside one.
