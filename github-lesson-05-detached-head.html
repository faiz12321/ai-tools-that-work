git: You are in 'detached HEAD' state. How do I fix it?

Short answer

It is not an error: HEAD now points at one commit instead of a branch, usually because you checked out an old commit. To just go back, run git switch main (or your branch's name). If you made commits you want to keep, run git switch -c new-branch-name first so the work lands on a branch.

Safety: commits made while detached are not on any branch. Before switching away, keep them with git switch -c or write down their hashes. Do not run git reset --hard or git checkout -f while you have uncommitted work you care about; both discard it.

Common mistakes with detached HEAD

  1. Reading the long message as an error. It is advice. The last line, 'HEAD is now at ...', tells you where you stand. Nothing is broken.
  2. Switching back without a branch. Commits made while detached are on no branch. If you want them, run git switch -c before you leave; finding them later means digging through git reflog.
  3. Force-moving with checkout -f or reset --hard. Both discard uncommitted changes. With a detached experiment in progress, that is an easy way to lose it.
  4. Assuming commits are saved because they exist. A commit no branch points to is safe only until garbage collection. A branch name is what keeps it reachable.
  5. Panicking and cloning again. The fix is one switch command; your history is intact.

Frequently asked questions

What does 'detached HEAD' mean?

HEAD is the name for where you are. Normally it points at a branch, and the branch moves with each commit. Detached means HEAD points directly at one commit instead, so no branch moves when you commit.

Is detached HEAD an error?

No. It is a normal way to look at an old commit. The long message is advice, not an error. You can build, run and test the old state, then switch back to a branch.

How do I keep work I made while detached?

Create a branch where you stand: git switch -c new-branch-name. The commits you made are now on that branch and safe to merge or push later.

What happens if I switch away without making a branch?

Commits you made while detached are no longer on any branch. They still exist for a while and git prints their hashes, but the easy moment to keep them is before you leave: git switch -c.

How do I get back to normal?

git switch main (or your branch's name) reattaches HEAD to the branch. If you made commits you want to keep, create a branch with git switch -c first.

Why did git put me here?

Usually because you checked out a commit hash, a tag, or something like HEAD~1 instead of a branch name. Checking out a branch reattaches; checking out a commit detaches.
