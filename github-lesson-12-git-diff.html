git: how do I see what changed? (git diff)

Short answer

git diff shows edits that are not staged yet. git diff --staged shows what is queued for the next commit. git diff A B compares two commits, and --stat condenses any of these to a summary. Lines with - are old, lines with + are new.

Safety: every form of git diff only reads; it cannot change anything. The trap to avoid is the wrong conclusion: a silent git diff means "working tree matches the staged copy", not "nothing changed anywhere".

Common mistakes with git diff

  1. Reading a silent git diff as "nothing changed". It only means the working tree matches the staged copy. Staged changes are invisible to it; check git diff --staged.
  2. Committing without reviewing the staged copy. git diff shows what is NOT in the commit. The commit contains what --staged shows. Review that one.
  3. Mixing up - and +. - is the old line being removed, + is the new line replacing it. In a commit-to-commit diff, - belongs to the first commit named.
  4. Expecting git diff to compare branches. Plain git diff never touches history. Give it two commits or a range, like git diff main..feature.
  5. Skimming the whole patch when you need the shape. --stat gives file names and counts first; open the full patch only for the files that matter.

Frequently asked questions

What does git diff show?

By default it shows edits in your working tree that are not staged yet: what you would still need to git add. Lines starting with - are the old version, lines with + are yours.

Why does git diff print nothing after git add?

Because plain git diff compares the working tree against the staged copy, and after git add they match. The change is not gone; run git diff --staged to see what is queued for the next commit.

How do I see staged changes?

Run git diff --staged. That is exactly what will go into the next commit, so it is the right review before committing.

How do I compare two commits?

Run git diff first-commit second-commit, for example git diff HEAD~1 HEAD to see what the last commit changed. You can also paste two hashes.

How do I get just a summary of changes?

Add --stat: git diff --stat HEAD~1 HEAD prints one line per file with counts of insertions and deletions instead of the full patch.

Can git diff damage anything?

No. git diff only reads and compares; it changes nothing. It is the safest command in this whole series.
