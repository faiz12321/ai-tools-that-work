No space left on device. How do I fix it?

Short answer

A write failed because the target disk had zero bytes free. Confirm which disk is full with df -h, rule out an inode shortage with df -i, then find what is eating the space with du -ah --max-depth=1 / | sort -h. When a running app holds the big file, empty it in place with truncate -s 0 instead of rm, and prove the fix by re-running the failed write.

Common mistakes with a full disk

  1. Deleting before measuring. df first, so you know which disk is full; then du, so you know what filled it. Guessing wastes time and can remove the wrong data.
  2. rm on a file an app is writing. The space may not come back until the app closes the file, and the app can crash. truncate empties the file in place.
  3. Forgetting inodes. No space left with free bytes showing means the inode table is full: too many small files. df -i tells the difference.
  4. Assuming a reboot fixes it. Whatever filled the disk starts writing again after boot. Only rotation or size limits prevent the refill.
  5. Ignoring the small failing write. A one-line log write failing does not mean the line was too big. It means the disk is at zero bytes free.

Frequently asked questions

Why does Linux say No space left on device?

A write needed bytes and the target disk had none left. One big file or millions of small ones can both cause it. df -h shows which mounted disk is at 100%.

Disk says full but df shows space free?

Check inodes with df -i: huge numbers of tiny files can use up the file slots while bytes remain. Also, a file deleted while a process still holds it open keeps its space until the process closes it; find those with lsof +L1.

Is it safe to truncate a log file?

truncate -s 0 empties the file but keeps its name and the app's handle, so logging continues. Never truncate a database or other binary data file: those have their own cleanup commands.

Why not just rm the big file?

If a process holds it open, the name is gone but the space is not freed until the process closes it, and the process can fail. truncate frees the space immediately while the file stays in place.

How do I find the biggest files on Linux?

du -ah --max-depth=1 /path | sort -h lists sizes sorted, biggest last. Drill into the biggest folder and repeat. ncdu does the same interactively.

How do I stop a disk filling up again?

Rotate logs with logrotate, cap the size of caches, and alert on disk usage. A bigger disk only postpones a writer that never stops growing.
