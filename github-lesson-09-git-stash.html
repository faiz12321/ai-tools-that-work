git: how do I save unfinished work and get it back? (git stash)

Short answer

git stash shelves your uncommitted changes and gives you a clean tree. Do the urgent thing, then git stash pop puts the work back and clears the shelf. git stash list shows what is parked.

Common mistakes with git stash

  1. Using the stash as long-term storage. Entries pile up with names like WIP on main, and a week later nobody knows what stash@{4} was for. Stash for minutes or hours, then pop.
  2. Forgetting untracked files. A brand-new file is not stashed by default, so the tree is not actually clean after git stash. Add -u or commit the new file first.
  3. Running git stash clear to tidy up. clear deletes every entry at once. If you are not sure, list first and pop or drop one entry at a time.
  4. Panicking when pop conflicts. A conflict on pop is not data loss: the entry stays on the stack and the conflict markers wait for you to resolve them, exactly like a merge.
  5. Stashing to avoid committing, then losing the thread. If the work is done, commit it. The stash is for interruptions, not for avoiding decisions.

Frequently asked questions

What does git stash do?

It takes your uncommitted changes out of the working tree and stores them on a stack called the stash. Your files go back to the last commit, and the shelved work waits until you ask for it.

How do I get my stashed work back?

Run git stash pop. It reapplies the most recent stash entry and removes it from the stack when it applies cleanly. Use git stash apply instead if you want to keep the entry.

How do I see what I have stashed?

Run git stash list. Each entry shows its position, like stash@{0}, and the commit it was made on.

Is stashed work safe?

Yes, the stash is a real commit inside your repository. But git stash drop and git stash clear delete entries, and an entry you drop by accident is hard to recover, so keep stashes short-lived.

Does git stash include new untracked files?

No, not by default: it only stashes changes to files git already tracks. Add -u to include untracked files.

What if git stash pop conflicts?

If the code moved on since you stashed, pop reports a conflict and keeps the entry on the stack. Resolve the conflict markers the same way as a merge, and nothing is lost.
