git: how do I throw away changes I have not committed? (git restore + git clean)

Short answer

Edits to a tracked file: git restore <file> puts back the committed version. Untracked junk files: git clean -n lists what would go, then git clean -f deletes it. Both are permanent - git cannot undo either, so look before you clean.

Common mistakes when discarding changes

  1. Using clean on a tracked file. clean only sees untracked files; it will never discard your edit to style.txt. Tracked edits are restore's job.
  2. Skipping the dry run. git clean -f deletes immediately and permanently. git clean -n shows the exact list first - reading it takes five seconds and has saved many home directories.
  3. Thinking -f alone removes folders. It does not. Untracked directories need -d (git clean -fd), and ignored files need -x. Each wider flag deletes more; widen only after the preview.
  4. Expecting an undo. Discarded edits and cleaned files were never committed, so git has no copy anywhere. The undo habit is upstream: commit or stash before you discard.

Frequently asked questions

How do I discard edits to a tracked file?

Run git restore <file>. The file goes back to exactly what the last commit holds, and the edits are gone permanently. (Older docs say git checkout -- <file>; restore is the modern spelling.)

How do I delete untracked files safely?

Run git clean -n first: it lists what would be removed without deleting anything. When the list matches your expectation, run git clean -f to actually delete. Untracked files deleted this way are not recoverable by git.

What is the difference between git restore and git clean?

restore works on tracked files: it discards edits by copying the committed version back. clean works on untracked files: it deletes them. One restores, one removes; they cover different halves of a messy tree.

Can git bring back a discarded edit or a cleaned file?

No. Neither the discarded edit nor the deleted untracked file was ever committed, so the reflog and object store know nothing about them. Both operations are final.

What about staged changes?

git restore only touches the working tree. To unstage, git restore --staged <file> moves the change out of the staging area (kept in the tree); a second plain restore then discards it.

How do I discard everything at once?

git restore . discards all tracked edits and git clean -fd removes untracked files and folders - after git clean -n showed you the list. Powerful and permanent; in this lesson we go file by file on purpose.
