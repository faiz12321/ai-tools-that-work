git: how do I read the commit history? (git log)

Short answer

git log --oneline lists commits from where you stand, but it cannot see other branches. git log --oneline --graph --all draws the whole picture. git show hash tells you exactly what one commit changed, and git log --oneline main..feature answers "what does that branch add?"

The situation
Someone added a button commit on the feature branch, but from main the log does not mention it. Find the commit, see exactly what it changed, and learn to answer three everyday questions: what happened here, what touched this file, and what does that branch add.

Common mistakes with git log

  1. Trusting the flat list as the whole repo. git log shows one line back from your current branch. Work on other branches is invisible until you add --all.
  2. Using git checkout to read an old commit. That detaches HEAD and invites stray commits. git show reads the commit and moves nothing.
  3. Expecting the file filter to search every branch. git log -- app.txt still starts from where you stand. Add --all if the file's history might live on another branch.
  4. Memorizing long hashes. The short prefix git prints is enough for git show and friends, as long as it is unique in the repo.
  5. Panicking that reading history can break something. It cannot. log and show are read-only; explore freely.

Frequently asked questions

How do I see my commit history?

Run git log --oneline. It lists the commits reachable from where you stand, newest first, one line each.

Why does git log not show my other branch?

git log only walks back from your current branch. Commits that exist only on another branch are invisible to it. Add --all to see every branch, and --graph to draw the shape.

How do I see what one commit changed?

Run git show followed by the commit's hash. It prints the author, date, message and the full diff. A short hash like bce6eb9 is enough.

How do I see the history of one file?

Run git log --oneline -- path/to/file. Only commits that touched that file appear, and only ones reachable from your current branch.

What does main..feature mean in git log?

It means: commits reachable from feature that are not reachable from main. It answers the everyday question, what does that branch add?

Is git log safe to run?

Yes, completely. git log and git show only read history; they change nothing. Explore as much as you like.
