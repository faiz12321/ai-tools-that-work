How to look inside a ZIP file without unpacking it

Short answer

A ZIP file can be damaged, or can be something else with a .zip name. This lesson builds a small read-only Python tool that opens a ZIP file with Python's zipfile module, counts what is inside, lists the first ten names, flags names that start like an absolute path or have a .. part, and asks Python to read every file back and compare it with its stored checksum. The tool has no code that unpacks anything. A clean report is not a safety check.

Common mistakes

  1. Trusting the name. The first version in this lesson only checks that the name ends in .zip. A plain text file with that name passes it.
  2. Unpacking to find out what is inside. Unpacking writes files. The tool lists the names and reads the contents back in memory instead, and tests check that nothing is created next to the ZIP file.
  3. Ignoring odd names. A name that starts with a slash or has a .. part could point outside the folder you unpack into. The tool flags those. Python's own documentation says never to extract archives from untrusted sources without prior inspection.
  4. Treating a clean report as a safety check. The tool does not look at what the files contain. It checks only that the archive opens, the names look ordinary and the stored checksums match.

Frequently asked questions

How do I look inside a ZIP file without unpacking it?

Open it with the zipfile module and ask for its list of members. That reads the index and does not write files. This lesson builds a small tool around that.

Will this unpack my ZIP file?

No. The tool has no code that extracts. Tests check that no file appears next to the ZIP file, including files with the unusual names in the practice archive.

Will this change my ZIP file?

No. The tool only reads it. A test checks that one small file has the same bytes and the same modified time before and after a run.

What does the checksum test do?

Python's testzip function reads every file in the archive and compares it with its stored checksum, returning the first bad file. The practice file has one letter changed, and the tool names the right file.

Does a clean report mean it is safe?

No. The tool does not look at what the files contain, and its name check uses only simple rules.

What about big or password-protected archives?

Over 200 MB declared, or with password-protected files, the contents are not tested and the tool says so. The declared size comes from the ZIP file itself, which can be wrong.
