How to check a settings (.ini) file for mistakes

Short answer

A settings file can look fine and still fail when a program reads it: a missing section header, a setting written twice or a lone percent sign. This lesson builds a small read-only Python tool that reads an .ini file with Python's configparser module, reports the first problem with its line number, lists the sections, and asks for every value the way a program would. The tool has no code that writes to a file. A clean report only means Python's reader accepted it.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Counting lines with an equals sign. The first version in this lesson counts them. It says nothing about a missing section header, a repeated setting or a value that cannot be used.
  2. Thinking Name and name are different settings. Python's default reader ignores case in setting names, so a setting written twice in different cases is reported as a repeat.
  3. Writing a lone percent sign in a value. Python's default reader treats % as special. The file reads fine, but asking for the value fails. Write %% for a literal one.
  4. Treating a clean report as proof the settings are right. The tool checks that Python can read the file and each value. It does not know what your program expects.

Frequently asked questions

How do I check an .ini file for mistakes?

Read it with the configparser module and see whether it raises an error. This lesson builds a small tool around that and also asks for every value.

Will this change my settings file?

No. The tool only reads the file. A test checks that all four practice files keep the same bytes and modified time.

Why does it show only one problem?

Reading stops at the first error. Fix it and run the tool again to see the next one.

Why is a repeated setting reported when the case is different?

Python's default reader treats names without regard to case, so Name and name are the same setting. The tool says line 4 of the practice file.

What is the problem with a % in a value?

Python's default reader uses % for references to other settings. A lone % passes reading but fails when the value is asked for, so the tool asks for every value. Write %% for a literal one.

Does a clean report mean my program will accept the file?

No. Other programs may follow other rules, and the tool does not check what the values mean.
