Check candidate sidecar names in a fictional Takeout-style folder

Short answer

Start with a name inventory, not a completeness claim. This PowerShell lesson looks for limited sidecar-name candidates in the SAME folder as each media filename. It reports missing and ambiguous candidates rather than guessing. A unique filename candidate is not proof of correct metadata, a readable photo, a correct date or a complete export.

Common mistakes

  1. Matching a JSON from another album. This version only considers siblings. Same base names in different folders are not interchangeable.
  2. Letting two photos claim one truncated name. Shared candidates are ambiguous for both photos. No first-match winner is chosen.
  3. Calling all unpaired JSON orphaned photos. Album metadata, unsupported naming and other JSON can be legitimate. This report does not know what each JSON means.
  4. Calling name coverage complete or correct. The checker does not parse JSON, decode media, compare titles, validate dates or compare the export with the online library. A status 0report is only candidate-name coverage.

Frequently asked questions

Does a unique pair prove the JSON belongs to that photo?

No. It is a filename candidate only. Contents, title, timestamp and media validity are not checked. Even invalid JSON can be a unique filename candidate, and the test suite demonstrates that limit.

Why not use one global filename map?

Different albums can contain the same names. A JSON in one folder must not satisfy a photo in another. This version compares full same-directory paths case-sensitively.

Does this support every Google Takeout naming pattern?

No. It includes classic .json, .supplemental-metadata.json, a limited 46-character stem cut and observed duplicate-marker forms. Those patterns come from open-source reports, not an official complete Google naming specification. Other valid forms may be unresolved.

Why is unpaired JSON not necessarily a missing photo?

A JSON may describe an album, use an unsupported name, or be one of several ambiguous candidates. This lesson does not parse it.

What does exit status mean?

0: selected media have unique one-to-one recognized candidate names and every discovered JSON is in such a pair.1: review missing/ambiguous/unpaired names or no selected media.2: input refused or an error. None means export completeness or correct dates.

What do the tests prove?

Small fictional cases cover folder boundaries, candidate ambiguity and refusals, plus fixture bytes and modification times before/after a report. No real Takeout export, Windows desktop or full naming coverage is tested.

Before you practise

Install PowerShell 7.4+ separately. Run the commands in pwsh, not Windows PowerShell 5.1 or Command Prompt. Ubuntu requires /usr/bin/test to reject special entries before PowerShell link inspection. This code needs a local unpacked folder, not a ZIP. It scans at most 5000 entries and a limited extension list: jpg,jpeg,png,gif,mp4,mov,heic. Hidden entries are included. Case-sensitive names and limited observed classic/supplemental/duplicate/truncated patterns are used; other valid Takeout forms may remain unresolved. No network/upload code is used, but cloud sync/other software are not controlled. A generated placeholder with a .jpg name is not an image and is never decoded here. Enumeration and reporting can still use memory/time; the entry limit is not a resource sandbox. Do not bypass execution-policy or security restrictions. Use your normal approved script workflow.
