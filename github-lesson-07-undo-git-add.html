git: how do I undo git add?

Short answer

Run git restore --staged filename. The file leaves the staging area but stays on disk exactly as it is; unstaging never deletes work. To unstage everything: git restore --staged .. Then check git status before you commit.

The situation

Safety: unstaging is safe for your files. The dangerous neighbor is git restore notes.txt without --staged (also written git checkout -- notes.txt): that one discards your edits to the file. The two commands differ by one flag.

Common mistakes with staging

  1. Dropping the --staged flag. git restore notes.txt discards your edits to the file itself. With --staged it only leaves the commit list. One flag separates safe from destructive.
  2. Committing first, fixing later. Once the draft is inside a commit, removing it means rewriting history. Unstage before you commit; it is one command and no rewriting.
  3. Deleting the file to unstage it. That removes your work too. Unstaging keeps the file and only changes the next commit.
  4. Trusting silence. git restore --staged printed nothing in this recording. That is not proof; git status is.
  5. Fearing git add . It is fine when you check what it staged. The mistake is committing without reading git status.

Frequently asked questions

How do I undo a git add?

Run git restore --staged filename. The file leaves the staging area and stays on disk, unchanged. Nothing is deleted.

Does unstaging delete my work?

No. Unstaging only changes what the next commit will include. The file itself stays exactly as it is. The destructive neighbor is git restore without --staged (or checkout --), which discards file edits.

How do I unstage everything at once?

git restore --staged . unstages every staged path from the current folder down, or git reset with no arguments unstages everything in the repository. Both keep your files.

What is the staging area for?

It is the list of changes the next commit will contain. git add puts changes on the list, git restore --staged takes them off, and git commit saves the list as a commit.

git restore --staged printed nothing. Did it work?

Silence alone proves nothing. Run git status: the file should move from 'Changes to be committed' to untracked or unstaged. Verify, do not assume.

I see git reset HEAD file in older answers. Is that the same?

Yes, it unstages the same way. git restore --staged is the newer, clearer spelling that current git suggests in git status output.
