git: delete untracked files safely (git clean)

Short answer

git clean -fd deletes untracked files and directories. Because they live nowhere in git's history, deletion is permanent - so git refuses to run plain git clean at all. The safe habit: preview with git clean -nd first, read the list, then delete with git clean -fd.

Safety: git clean -fd is one of the few git commands that destroys data with no undo: untracked files are not in any commit, stash or reflog, and there is no trash. That is why git itself refuses to run it without -f, -n or -i - and why every real run should start with the -n dry run. The lab has no remote.

Common mistakes with git clean

  1. Running -fd without a dry run. The list you get from -nd is the exact list -fd will delete. Ten seconds of reading beats an unrecoverable mistake.
  2. Believing undo exists. There is no git checkout, no reflog, no stash for untracked files. clean is final. If a file might matter, move it aside or commit it first.
  3. Forgetting -d for directories. Without -d, git clean leaves untracked directories like build/ in place. With -x it will also take ignored files - powerful and dangerous in one flag.
  4. Expecting it to touch tracked changes. clean never modifies tracked files. Unstaged edits to tracked files are git restore territory - also destructive, also worth a second thought.

Frequently asked questions

How do I remove untracked files in git?

git clean -fd deletes untracked files and directories. Always preview first with git clean -nd, which lists exactly what would be removed without deleting anything.

Why does git clean say "refusing to clean"?

Git requires you to say how seriously you mean it: -f to force deletion, -n for a dry run, or -i for interactive. Plain git clean refuses because deletion of untracked files is permanent - they exist nowhere in git's history.

Can I undo git clean?

No. Untracked files are not in any commit, the stash, or the reflog - once git clean deletes them they are gone, with no trash folder. That is why the dry run (-n) habit matters.

What is the difference between git clean -f, -d and -x?

-f deletes untracked files. -d also includes untracked directories. -x also removes ignored files (like build output in .gitignore); without -x, ignored files are left alone. Combine as needed: git clean -fdx.

Does git clean touch modified or staged files?

No. git clean only ever removes untracked paths. Tracked files with uncommitted changes are untouched - those need git restore (unstaged) or git restore --staged plus git restore (staged), which are different commands.
