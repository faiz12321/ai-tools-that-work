git: work on two branches at once (git worktree)

Short answer

git worktree add -b hotfix ../myrepo-hotfix main gives you a second working folder for the same repo, with a new branch checked out in it. Your first folder keeps its branch and its uncommitted work exactly as it was. Manage worktrees with git worktree list and git worktree remove <path>.

Below is a hands-on practice run with real recorded output. You are mid-feature, a hotfix comes in, and you handle it in a second folder without stashing or committing half-done work.

The situation
You are deep in a feature with uncommitted changes everywhere. Production needs a hotfix now. Switching branches means stashing or a fake commit - or does it? A worktree opens a second folder on the same repo so both jobs sit side by side.

Common mistakes with git worktree

  1. Cloning the repo a second time. A second clone duplicates all history and loses sight of the original. A worktree shares one object store - instant and always in sync.
  2. Trying to check out the same branch twice. Git refuses: a branch lives in exactly one worktree at a time. Give the second folder its own branch.
  3. Deleting the worktree folder by hand. Then git still thinks it exists. Use git worktree remove - or git worktree prune if the folder is already gone.
  4. Forgetting the branch survives the worktree. remove takes away the folder, not the branch. The branch stays in git branch until you delete it deliberately.

Frequently asked questions

What is a git worktree?

A second (or third) working folder attached to the same repository. Each worktree has its own checked-out branch and files on disk, but they all share one .git object store and history.

How do I work on two branches at the same time in git?

git worktree add -b hotfix ../myrepo-hotfix main creates a new folder ../myrepo-hotfix with branch hotfix checked out. Your original folder keeps its branch and uncommitted work untouched.

Can the same branch be checked out in two worktrees?

No. Git refuses to check out a branch that is already checked out in another worktree - two folders editing one branch would collide. Each worktree needs its own branch.

How do I remove a git worktree?

git worktree remove <path> deletes the working folder and unregisters it. It refuses if the worktree has uncommitted or untracked changes; verify afterward with git worktree list. Do not just delete the folder by hand - if you did, run git worktree prune to clean up the record.

Does git worktree copy the whole repository?

No. The new folder gets its own working files and a small administrative stub, but all history and objects stay shared in the original repository. It is fast and cheap compared to a second clone.
