git: "Cannot delete branch 'feature' checked out at ..." - how do I delete my current branch?

Short answer

You are standing on the branch you want to delete, and git will not remove the ref your HEAD points at. Step off first: git switch main, then git branch -d feature - the same command now succeeds. Deleting removes only the label (a ref file); the commits are untouched and the printed hash (was 090bef8) can recreate the label. If the path in the error is a folder you forgot, that is a linked worktree holding the branch - switch or remove it first.

Common mistakes with the checked-out refusal

  1. Reaching for -D to force it. -D overrides the not-fully-merged check (lesson 48), not the checked-out check. No flag overrides this one - git switch away first.
  2. Confusing the two refusal messages. 'not fully merged' is about commit safety; 'checked out at PATH' is about where you stand. Read which one you got - the fixes are different.
  3. Deleting the folder named in the error. When the path is a linked worktree, rm -rf strands its admin files (repairable with git worktree prune, lesson 27). Visit the folder and git switch, or git worktree remove it.
  4. Fearing history loss. Deleting a branch removes a 41-byte ref file, not commits. Anything merged into another branch is completely safe; even unmerged tips linger for weeks and are restorable from the printed hash.

Frequently asked questions

What does 'checked out at PATH' mean?

That work tree currently has the branch as its HEAD. Git will not delete a ref your HEAD points at. The PATH is your main folder - or a linked worktree you forgot about.

How do I delete my current branch?

git switch main first, then git branch -d feature. If it is fully merged the delete succeeds immediately; the commits are never touched - only the label file is removed.

Is this the same as 'not fully merged'?

No. 'Not fully merged' protects unmerged commits (override with -D after checking). 'Checked out' protects HEAD's footing and has no force override - you must move to another branch.

What if the path is a folder I do not remember creating?

That is a linked worktree (git worktree list shows all of them). A branch can be checked out in only one place, so git blocks the delete. Switch that folder to another branch or run git worktree remove on it, then delete.

Does deleting the branch lose my commits?

No. The branch is a tiny ref file; commits live in the object store. Merged commits stay reachable forever; unmerged tips linger for weeks. git branch feature <hash> with the printed hash restores the label.
