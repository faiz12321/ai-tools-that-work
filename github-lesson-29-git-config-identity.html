git: "Please tell me who you are" (git config user.name)

Short answer

Every commit carries an author name and email, and git refuses to commit until it knows yours. Fix it once, everywhere: git config --global user.email "you@example.com" and git config --global user.name "Your Name". Leave off --global to set an identity for one repository only.

Below is a hands-on practice run with real recorded output. A fresh machine, a first commit, and the famous refusal - then the two-line fix and proof it stuck.

New laptop, fresh repo, first commit - and git answers "Author identity unknown... Please tell me who you are" and refuses. Nothing is broken: git simply will not guess who to write into history.

Common mistakes with git identity

  1. Thinking the error is a broken install. It is a missing setting, by design. Git refuses to invent an author for history.
  2. Setting it repo-locally and wondering why the next repo fails again. Without --global the identity lives in one repo's .git/config. For your default, use --global once.
  3. Editing old commits' author casually later. The identity is baked into each commit's hash. Changing authorship after the fact rewrites history - fine before pushing, disruptive after.
  4. Assuming git verifies the email. It is a label, not proof. Choose the email you want public in commit history - on GitHub, match one on your account for contribution credit.

Frequently asked questions

How do I fix "Please tell me who you are" in git?

Set your identity: git config --global user.email "you@example.com" and git config --global user.name "Your Name", then commit again. Git stamps every commit with this name and email and refuses to commit without them.

What does "fatal: empty ident name not allowed" mean?

Git tried to auto-detect your name and email from the operating system and found nothing usable. It needs a real name and email for the commit's author and committer fields - set them with git config.

What is the difference between git config --global and without --global?

--global writes to your user-wide ~/.gitconfig and applies to every repository. Without it, the setting goes into the current repository's .git/config only - useful for a work identity in work repos and a personal one elsewhere. Local beats global when both are set.

Does my git identity have to be my real name or GitHub email?

It is just a label written into each commit - git does not verify it. Use the name and email you want shown in history. For GitHub contribution credit, match the email to one on your GitHub account.

How do I check my current git identity?

git config --list --show-origin | grep user shows user.name and user.email and which file each came from. Or ask one at a time: git config user.email.
