git: "your current branch 'main' does not have any commits yet" - is my new repo broken?

Short answer

No - the repository is healthy and simply empty. HEAD points at an unborn branch: a name (refs/heads/main) with no commit behind it. That is why git log fails, git branch lists nothing (refs are created by commits), and git show HEAD answers 'ambiguous argument'. Meanwhile git status, git add and git diff --cached all work. Create a file, git add, git commit - the root commit creates the branch and every error disappears.

The situation
You ran git init in a new project folder and typed git log to see the empty history. Instead: fatal: your current branch 'main' does not have any commits yet. git branch lists nothing at all, and git show HEAD answers with 'ambiguous argument'. Did init fail? Is the repository corrupt?

Common mistakes in a brand-new repository

  1. Deleting .git and re-initialising. The init did not fail - 'Initialized empty Git repository' means zero commits, and re-running init lands you in the identical state. Make a commit instead.
  2. Trying to create the branch by hand. git status already says you are ON main - HEAD holds the name as a promise. The first commit fulfills it; you cannot check out or create what has no commit to point at.
  3. Reading 'ambiguous argument HEAD' as a syntax error. The '--' hint in that message is boilerplate for path-vs-revision ambiguity. In a fresh repo the real meaning is: HEAD does not resolve yet. It is about emptiness, not syntax.
  4. Trusting git branch over git status before the first commit. git branch lists existing refs (zero, until a commit writes one); git status reads HEAD's target name directly. Pre-commit, status is the reliable view of where you are.

Frequently asked questions

What does 'does not have any commits yet' mean?

The repository is fine and empty. HEAD points at a branch name with no commit behind it, so history commands have nothing to show. The first commit creates the branch and the message disappears.

Why is git branch empty while git status says 'On branch main'?

git branch lists ref files, and refs are written by commits - zero commits means zero refs. git status reads the branch name straight out of .git/HEAD without resolving it, so both are telling the truth.

What about 'ambiguous argument HEAD: unknown revision'?

HEAD cannot be resolved into a commit because its branch has none. The '--' hint is boilerplate; the cause is the unborn branch. Scripts running git show, git reset HEAD or git rev-parse HEAD in a fresh repo all stop on this line until the first commit lands.

Which commands work before the first commit?

git status, git add, git diff --cached (against the empty tree), git symbolic-ref HEAD and git commit all work. Only commands that must resolve HEAD to an existing commit - log, show HEAD, rev-parse HEAD, tag, reset - fail.

What is a root commit?

The first commit in a history - the only one with no parent, marked '(root-commit)' in the output. Every later commit chains back to it, and creating it is what writes the branch ref file for the first time.
