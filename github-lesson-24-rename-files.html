git: does git track renames? (git mv)

Short answer

git mv old new renames and stages in one step - but git never stores a rename record. It stores snapshots and detects renames later from content similarity. That is why plain mv plus git add -A shows the exact same R flag, and why git log --follow -- <file> can walk history across a rename.

Common mistakes with renames in git

  1. Believing git mv writes a rename record. There is no rename object in git storage. The R you see is detected on demand by comparing a deleted path with an added path of similar content - proven below, where plain mv earns the same R.
  2. Reading log without --follow. A plain git log -- summary.txt stops at the rename commit, making the file look two days old. --follow keeps walking through the old name.
  3. Renaming and rewriting in one commit. Detection works on similarity (50% by default). Rename + big edit can read as delete + add, and the file's history chain visually breaks. Rename in its own commit when history matters.
  4. Case-only renames on Windows/macOS. The filesystem thinks Readme.md and README.md are the same file, so a plain mv may not register. git mv -f Readme.md README.md forces it.

Frequently asked questions

How do I rename a file in git?

git mv old-name new-name stages the move in one step. But a plain mv followed by git add -A gives the same result: git status shows 'renamed: old -> new' either way, because git detects renames rather than recording them.

Does git track file renames?

No. git stores snapshots of tree contents, not rename events. When status, diff or log compares commits, git notices that a deleted file and an added file have identical or similar content and presents the pair as a rename. That is why detection works no matter how the file was moved.

How do I see a file's history across a rename?

git log --follow --oneline -- new-name. The --follow flag tells log to keep walking the history of the file's previous names; without it, the log stops at the rename commit.

Why does my rename show as delete plus add?

Rename detection has a similarity threshold (50% by default). If the file was renamed AND heavily edited in the same step, git may report a delete and an add instead. Committing the rename separately from big edits keeps the history clean.

How do I change only the capitalization of a file name?

On case-insensitive filesystems (default Windows and macOS), a plain mv of 'Readme.md' to 'README.md' may not register. git mv -f Readme.md README.md forces git to record the change.
