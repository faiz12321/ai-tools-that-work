git: how do I copy one commit to another branch? (git cherry-pick)

Short answer

Switch to the branch that needs the change, then git cherry-pick <commit-hash>. git replays that one commit's change as a new commit on your branch and leaves everything else on the other branch behind.

Common mistakes with cherry-pick

  1. Picking onto the wrong branch. The new commit lands on your CURRENT branch. Run git switch main (or your target) first, then pick. Check with git status --short --branch before you pick.
  2. Merging when you wanted one commit. git merge feature would drag the broken WIP commit along. If you want exactly one change, name exactly one hash.
  3. Confusing the two hashes later. The fix exists twice: 269e877 on feature and 58f7dad on main. They are different commits with the same change. When feature later merges, git is smart about the duplicate content, but the double entry in history is normal.
  4. Freezing on a conflict. A conflicted cherry-pick pauses mid-operation. Resolve, git add, git cherry-pick --continue - or --abort to give up cleanly.

Frequently asked questions

How do I copy one commit to another branch?

Switch to the branch that should receive the change, then run git cherry-pick <commit-hash>. git applies that one commit's change as a new commit on your branch. The rest of the other branch stays behind.

Why does the cherry-picked commit have a different hash?

Cherry-pick does not move the original commit; it creates a new commit with the same change and message. A different parent and timestamp means a different hash, so the same fix lives under two hashes on the two branches.

How is cherry-pick different from merge?

Merge brings every commit from the other branch. Cherry-pick brings exactly the commits you name. Use merge when you want the whole branch, cherry-pick when you want one fix out of it.

Can I cherry-pick more than one commit?

Yes: list several hashes, or a range like git cherry-pick A..B which replays every commit after A up to and including B, oldest first.

What if the cherry-pick conflicts?

git pauses and marks the conflicted files. Resolve them, git add the files, then git cherry-pick --continue. To abandon the whole operation, git cherry-pick --abort returns you to the pre-pick state.

Does cherry-pick remove the commit from the original branch?

No. The original branch is untouched. Cherry-pick copies the change; nothing moves or is deleted.
