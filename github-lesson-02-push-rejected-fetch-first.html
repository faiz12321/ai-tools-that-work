git push: error: failed to push some refs. How do I fix it?

Short answer

The remote has commits you do not. Join them with yours first: git pull --no-rebase to merge (or git pull --rebase), then git push again. Do not answer with --force: that overwrites the other work.

Common mistakes with a rejected push

  1. Reaching for git push --force. It overwrites the remote, erasing the very work git just told you about. Force is for branches only you use.
  2. Cloning again instead of pulling. A fresh clone sidesteps the problem but abandons your local commit. Pull joins both lines of work.
  3. Skipping the hint lines. They name the cause (the remote contains work you do not have) and the fix (integrate it, then push).
  4. Trusting git status for remote news. status only knows the last fetch; here it still said ahead by 1 while the remote had moved. A fetch refreshes it.
  5. Assuming every pull merges cleanly. When both sides edit the same lines, git stops with a conflict. That is normal, not corruption: resolve, add, commit.

Frequently asked questions

Why was my push rejected?

The remote branch moved ahead of yours: it has commits you do not. git refuses to lose them, so it asks you to integrate the remote work before pushing.

Pull with merge or rebase?

git pull --no-rebase merges, as recorded here. git pull --rebase replays your commits on top of theirs. Both end pushable; a merge keeps the true join visible.

Is force push ever the right answer?

Only when you truly mean to replace the remote history, for example a branch only you use. Never as a reaction to this error: it overwrites the work git just told you about.

Why did git status say ahead by 1 when the remote had more?

status compares against what git last fetched. It had not fetched the new commit yet. git fetch, or the pull, refreshes that picture.

What if the pull stops with a conflict?

Both sides changed the same lines. Open the files, choose the right content, git add the files, git commit, then push.

Fetch first or non-fast-forward: which is it?

Both bracket reasons mean the same thing: the remote moved ahead, so integrate its work before pushing.
