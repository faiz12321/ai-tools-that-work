git: how do I get back a commit I deleted? (git reflog)

Short answer

git reflog is a journal of everywhere HEAD has pointed. Find the lost commit's hash there, then git reset --hard <hash> (on a private branch) puts it back. Commits are recoverable; uncommitted edits destroyed by a hard reset are not.

Common mistakes with lost commits

  1. Assuming the commit is truly gone. A commit orphaned by reset still sits in the object store. The reflog is the map back to it - check there first, before redoing work.
  2. Expecting uncommitted work to be recoverable too. It is not. reset --hard wipes working-tree edits with no journal entry. Commit or stash before any hard reset.
  3. Waiting weeks to recover. Reflog entries expire (about 90 days reachable, 30 days unreachable) and git gc prunes objects. Recover the same day you notice.
  4. Resetting shared branches to old hashes. Recovery by reset rewrites the branch. Fine for your own local work; on a pushed branch it strands everyone who pulled. Revert (lesson 15) is the shared-history-safe cousin.

Frequently asked questions

I ran git reset --hard and lost a commit. Is it gone?

Usually not. Commits stay in the object store and git reflog lists where HEAD pointed, including the lost commit. Reset back to its hash to restore it. Uncommitted changes, however, are not in the reflog and are truly gone.

What does git reflog show?

A journal of every place HEAD has pointed: commits, resets, checkouts, rebases. Each line has a hash, a HEAD@{n} index, and the action that moved HEAD there.

How do I restore a commit found in the reflog?

On a private branch, git reset --hard <hash> moves the branch back to that commit. A gentler option is git branch rescue <hash> to pin a branch on it first, then inspect before resetting.

What does HEAD@{1} mean?

It names where HEAD was one move ago. HEAD@{0} is the current position, HEAD@{1} the previous one, and so on down the reflog journal.

How long does the reflog keep entries?

By default, entries expire after 90 days for reachable commits and 30 days for unreachable ones, and git gc prunes old objects. Recover promptly rather than relying on it forever.

Does the reflog save uncommitted work?

No. reset --hard destroys uncommitted edits permanently; the reflog only tracks commits and HEAD positions. Stage or commit anything you cannot afford to lose before a hard reset.
