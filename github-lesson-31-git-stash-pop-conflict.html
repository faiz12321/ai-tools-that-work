git: stash pop merge conflict - resolve and drop (git stash pop)

Short answer

A conflicted git stash pop loses nothing: git keeps the stash entry and writes both versions into the file between markers. Edit the file to the final content you want, remove the <<<<<<<, ======= and >>>>>>> lines, then git add the file and git stash drop to clear the kept entry.

Common mistakes with a conflicted stash pop

  1. Panicking that the stash is gone. On conflict the drop is skipped - git stash list still shows the entry. Your work exists twice until you resolve.
  2. Committing the marker lines. The <<<<<<<, ======= and >>>>>>> lines are not content. If they reach a commit, the file is broken for everyone. Remove all three before git add.
  3. Dropping before adding. git stash drop permanently deletes the kept entry. Only drop after git add has accepted your resolved file - until then the stash is your undo.
  4. Forgetting a second conflicted file. Pop can conflict in several files at once. git status lists every "both modified" path - resolve them all before moving on.

Frequently asked questions

What does "CONFLICT (content): Merge conflict" on git stash pop mean?

The stashed change and a commit made since the stash both touched the same lines. Git applied what it could, wrote conflict markers into the file, and - unlike a clean pop - kept the stash entry so nothing is lost.

How do I resolve a git stash pop conflict?

Open the conflicted file, decide what the final content should be (yours, the stashed version, or a blend), delete the marker lines, then git add the file and git stash drop to remove the kept stash entry.

Did git stash pop delete my stash when it conflicted?

No. Pop is apply plus drop, but when the apply conflicts, git skips the drop and prints "The stash entry is kept in case you need it again." git stash list still shows it until you drop it yourself after resolving.

What do "Updated upstream" and "Stashed changes" mean in the markers?

"Updated upstream" is the version currently committed on your branch; "Stashed changes" is the version from the stash you are popping. The ======= line separates the two.

Can I undo a conflicted stash pop?

Yes, while unresolved: git restore --source=HEAD svc/config.txt returns the file to the committed version, and the stash entry is still in git stash list, so you can try again. Nothing was dropped.
