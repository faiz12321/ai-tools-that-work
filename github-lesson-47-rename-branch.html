git: rename a branch locally and on the remote. How do I do it?

Short answer

Three moves, not one. 1) git branch -m old-name new-name renames the LOCAL branch - commits and history stay put, only the label moves. 2) git push -u origin new-name publishes the new name on the remote and re-points your upstream (right after step 1 it still tracks the OLD remote name - that is normal). 3) git push origin --delete old-name retires the old remote branch. Teammates clean up with git fetch --prune and rename their own local copy the same way.

Common mistakes with renaming branches

  1. Stopping after git branch -m. The local rename feels done - but the remote still serves the old name, your upstream still points at it, and your next plain git push recreates the old branch remotely. The rename is three moves; -m is one of them.
  2. Deleting the old remote branch first. If a pull request is open against the old name, deleting it usually closes the PR. Push the new name, migrate or re-open the PR, THEN delete the old branch.
  3. Forgetting the teammates. Their clones keep a stale origin/old-name ref and their own old-named local branch. Send the three commands (fetch --prune, branch -m, branch -u) when you announce the rename, or the old name keeps resurrecting.
  4. Renaming branches you do not own. main, develop, release branches - a rename there is a force-push-class event for the whole team. Scratch and feature branches rename freely; shared long-lived branches need coordination or an alias instead.

Frequently asked questions

How do I rename a local git branch?

git branch -m old-name new-name (or just git branch -m new-name while on it). Instant and local: commits, hash, reflog and upstream move to the new label. The name is only a pointer - nothing is copied or merged.

How do I rename a branch that is already pushed?

There is no remote rename. 1) git branch -m old-name new-name. 2) git push -u origin new-name (publishes + re-tracks). 3) git push origin --delete old-name (retires the old name). Teammates run git fetch --prune.

Why does my renamed branch still track the old remote name?

git branch -m carries your upstream setting to the new name, so right after the rename, branch -vv shows it tracking the OLD remote branch. Expected. git push -u origin new-name publishes the new branch and re-points the upstream in one step.

What happens to pull requests and teammates when I rename?

PRs are tied to the remote branch name: deleting the old one usually closes its PR - push the new name first. Teammates keep a stale remote ref until git fetch --prune, and rename their own local branch with git branch -m + git branch -u origin/new-name.

What is the difference between git branch -m and -c?

-m MOVES (old name gone), -c COPIES (both names exist, same commit). For a rename you want -m; -c bookmarks the old label.
