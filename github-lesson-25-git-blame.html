git: who changed this line, and when? (git blame)

Short answer

git blame <file> labels every line with the commit, author and date of its last change. Go deeper with git log -L 2,2:<file> to replay one line's whole history, or git log -S 'text' --oneline to find the commit that added a string. Blame answers who and when; git show <hash> answers why.

Common mistakes with git blame

  1. Reading blame as "who wrote this". Blame names the LAST commit to touch each line. A reformat or a moved block repaints the whole file. The original author lives deeper, in git log -L.
  2. Stopping at who. Blame never tells you why. The commit hash in column one is the door: git show that hash for the message and the diff.
  3. Hunting with grep over the current tree. If the line was deleted, grep finds nothing. git log -S 'text' searches the whole history for when the text's count changed.
  4. Using blame for blame. The name is unfortunate. The healthy use is "who knows the context on this line" - a routing tool for questions, not a verdict.

Frequently asked questions

How do I see who changed a specific line in git?

git blame filename labels each line with the commit hash, author and date of its most recent change. Narrow it with git blame -L 5,10 filename to look at just lines 5 to 10.

Does git blame show who originally wrote a line?

No - it shows the most recent commit to touch that line. If someone reformatted the line last week, blame names them, not the original author. Use git log -L 5,10:filename to see the line's full history.

How do I see the history of one line or function?

git log -L 10,20:filename shows every commit that touched lines 10-20, with the diffs. git log -L :functionName:filename does the same for a whole function.

How do I find the commit that introduced a string?

git log -S 'the string' --oneline lists commits where the number of occurrences of that string changed - the pickaxe. Add -p to see the diffs.

Can git blame tell me why a line changed?

No. Blame gives who and when (and which commit). The why lives in the commit message and diff: run git show on the hash blame prints.
