git: I deleted a file and committed - how do I get it back?

Short answer

Find the deletion commit with git log --diff-filter=D --name-status --oneline -- <file>, then copy the last good version out of its parent: git restore --source=<hash>^ -- <file>. The file comes back to your working tree untracked - git add and commit to keep it.

Common mistakes when recovering a deleted file

  1. Restoring from the deletion commit itself. The file is already gone in that commit; its copy lives in the parent, which is what ^ points at.
  2. Assuming the file is tracked again. A plain git restore --source writes the working tree only. The file is untracked until you git add and commit it.
  3. Expecting git to recover an untracked file. If the file was deleted before any commit or add, there is no copy in the object store. That is an OS-level recovery job (trash, backup, snapshot), not a git one.
  4. Grabbing the wrong deletion. A file deleted, restored and deleted again has several deletion commits in the filtered log. Check the list and restore from the parent of the one you mean.

Frequently asked questions

How do I find when a file was deleted in git?

Run git log --diff-filter=D --name-status --oneline -- path/to/file. It lists only commits where that path was deleted, so the deletion commit shows up directly.

How do I restore a deleted file from an earlier commit?

Run git restore --source=<deletion-commit>^ -- path/to/file. The ^ means the commit's parent, which still holds the last good copy. On older git, git checkout <deletion-commit>^ -- path/to/file does the same and also stages it.

Why does the restored file show as untracked in git status?

git restore --source writes the bytes to your working tree only. The index still matches HEAD, where the file is gone, so git sees it as untracked. Run git add and git commit to track it again, or pass --staged --worktree to restore to both.

Can git recover a file I deleted but never committed?

No. git can only hand back versions it stored: committed or at least staged content. A file deleted while untracked has no copy in the object store; use OS-level recovery (trash, backups, filesystem snapshots) instead.

What if the file was deleted more than once?

The filtered log lists every deletion commit for the path. Pick the deletion you actually mean - usually the most recent one - and restore from its parent.

Does restoring overwrite a file that exists now?

Yes: if a file with the same path exists in your working tree, git restore replaces it with the historical copy. Check git status and the current file first if you are unsure.
