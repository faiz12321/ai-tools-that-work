Fix a git error

The exact messages people hit, what they actually mean, and the safe way out.

  • 01git: fatal: not a git repository. How do I fix it?Find where your project is, move into it and let git see the repository.
  • 02git push: error: failed to push some refs. How do I fix it?The remote moved ahead; pull to merge its work with yours, then push again.
  • 03git merge: CONFLICT (content). How do I fix it?Both branches changed the same line; choose the final text between the markers, then add and commit.
  • 04git: You are in 'detached HEAD' state. How do I fix it?Detached HEAD is a workbench, not an error: look around, then keep any new work with git switch -c.
  • 05git: error: pathspec did not match. How do I fix it?The name does not exist as a branch, tag or file: list your branches, then switch to it or create it.
  • 06git: fatal: refusing to merge unrelated histories?Two branches with no shared commit: when they truly belong together, join them with --allow-unrelated-histories.
  • 07git: stash pop merge conflict - resolve and dropA conflicted git stash pop loses nothing: the stash entry is kept and both versions stay in the file.
  • 08git: "Need to specify how to reconcile divergent branches" on pullBoth sides moved and git will not choose for you: answer once with git config, then pull.
  • 09git: "warning: LF will be replaced by CRLF" - what it meansNothing failed: git warns it will convert line endings between Linux and Windows.
  • 10git: "error: src refspec main does not match any" on pushYour side has no ref with that name: the branch has no commits yet, or the name was typed wrong.
  • 11git: "Another git process seems to be running" (index.lock)A crashed process left its do-not-disturb flag in .git/index.lock; reads pass, writes refuse.
  • 12git: "Your branch is ahead of 'origin/main' by N commits"Not an error - N local commits the remote does not have yet. Review what a push would send.
  • 13git: "You have not concluded your merge (MERGE_HEAD exists)"A merge stopped on conflicts is a state: MERGE_HEAD marks it until you commit or git merge --abort.
  • 14git: your local changes would be overwritten by checkout. How do I fix it?The refusal is protection, not breakage: stash the draft, commit the milestone, or discard - then switch.
  • 15git: "the branch is not fully merged" - how do I delete it?The safe delete refuses when commits would be orphaned: merge wanted work first; -D only for abandoned work.
  • 16git: "untracked working tree files would be overwritten by merge"The merge will not overwrite files it cannot restore: inspect with git show, move drafts aside, or stash -u.
  • 17git: "cannot rebase: You have unstaged changes"Rebase demands a clean tree: stash, rebase, stash pop - or let --autostash do the dance.
  • 18git: "warning: adding embedded git repository" - why is my folder empty?The folder had its own .git, so git stored a pointer, not files. Repair: rm --cached, delete the nested .git, re-add.
  • 19git: CONFLICT (modify/delete) - edited on one side, deleted on the otherReview the surviving version, then vote: git add keeps the file, git rm deletes it, commit concludes.
  • 20git push: "refusing to update checked out branch"The remote was made with plain git init and has a branch checked out. Fix: migrate it to a bare repo.
  • 21git: CONFLICT (add/add) - two branches created the same fileEdit to the final version (or checkout --ours/--theirs), git add, commit.
  • 22git: fatal: cannot lock ref - why can't I create my branch?A branch named feature already exists, so feature/api is impossible: rename the blocker with git branch -m.
  • 23git: "your current branch 'main' does not have any commits yet"Not broken - the repo is healthy and empty. HEAD points at an unborn branch; the first commit creates it.
  • 24git: "Cannot delete branch 'feature' checked out at ..."You are standing on the branch you want to delete: switch to another branch first, then git branch -d works.

Undo and recover

Get back lost commits, deleted files and wrong moves - or undo them without rewriting shared history.

  • 25git: how do I undo the last commit?Remove the last commit but keep its changes: reset --soft vs --mixed vs --hard, and when revert is the safe choice.
  • 26git: how do I undo git add?Unstage without losing work: git restore --staged takes a file off the commit list and keeps it on disk.
  • 27git: how do I fix the last commit?git commit --amend rewrites the message or folds in a forgotten file while the commit is still yours alone.
  • 28git: how do I undo a commit without rewriting history?git revert adds a new commit that cancels the bad one, so shared history stays intact.
  • 29git: how do I get back a commit I deleted?git reflog journals every HEAD move, so a commit lost to reset --hard can be restored.
  • 30git: how do I throw away uncommitted changes?git restore discards tracked edits; git clean -n previews and -f deletes untracked files.
  • 31git: which commit broke it? (git bisect)git bisect halves the suspects each run until it names the commit that broke the test.
  • 32git: I deleted a file and committed - how do I get it back?git log --diff-filter=D finds the deletion commit; git restore --source brings the file back.
  • 33git: make your repo match the remote exactlyThe real "force pull": git fetch origin, then git reset --hard origin/main.
  • 34git: push --force vs --force-with-lease ("stale info")Plain --force overwrites the remote, no questions asked; --force-with-lease refuses when someone pushed.
  • 35git: committed to the wrong branch? Move the commitsBranches are movable pointers: branch first, reset, switch - the commits keep their hashes. A local-only fix.
  • 36git revert: "is a merge but no -m option was given" - undo a mergeA merge has two parents, so revert needs -m to pick the side to keep; re-merging needs a revert of the revert.

Everyday git skills

The commands you use all the time, practised once properly: branches, history, stash, remotes and tags.

  • 37git: how do I save unfinished work and get it back?git stash shelves uncommitted changes for a clean tree; git stash pop brings them back.
  • 38git: how do I create, switch, and delete branches?git branch makes a label, git switch moves to it, git branch -d deletes only after git checks it is safe.
  • 39git: how do I read the commit history?git log --oneline lists, --graph --all draws the true shape, git show inspects one commit.
  • 40git: how do I see what changed?git diff shows unstaged edits, --staged shows what is queued, diff A B compares two commits.
  • 41git: how do I make git ignore files?A pattern in .gitignore hides untracked noise; a tracked file needs git rm --cached first.
  • 42git: how do I copy one commit to another branch?git cherry-pick replays a single commit on your current branch as a new commit.
  • 43git: how do I mark a release point?git tag -a pins an annotated tag (message, tagger, date) on any commit, even an older one.
  • 44git: fetch vs pull - what is the difference?git fetch updates only the origin snapshot - your files stay put; git pull is fetch plus merge.
  • 45git: rebase vs merge - which one and when?Merge keeps the true shape with a two-parent commit; rebase replays your commits for a straight line.
  • 46git: does git track renames? (git mv)git mv renames in one step; git detects renames from content, it does not store them.
  • 47git: who changed this line, and when? (git blame)blame labels every line with its last-changing commit; log -L replays a line's history.
  • 48git: switch -c vs checkout -b (what's the difference?)Both create and move to a new branch; switch is the modern, branch-only spelling.
  • 49git: work on two branches at once (git worktree)git worktree add opens a second folder on the same repo with its own branch.
  • 50git: delete untracked files safely (git clean)git clean -fd deletes untracked files permanently, so git refuses without -f, -n or -i.
  • 51git: "Please tell me who you are" (git config user.name)git refuses to commit until it knows your author name and email. Set them once with git config.
  • 52git: find who committed what, whenFilter history instead of reading it: git log --author for one person, --since/--until for dates.
  • 53git: what is "origin"? (git remote -v)"origin" is not a keyword - it is the default nickname for the repo you cloned from.
  • 54git: "no upstream branch" on pushGit will not guess where a new branch belongs: push it once with git push --set-upstream.
  • 55git: how do I delete a branch on GitHub? (remote branch)git branch -d deletes only the local branch; the GitHub copy survives until git push origin --delete.
  • 56git: squash your last N commits into one (rebase -i)Draft in many commits, publish one story: git rebase -i HEAD~N folds them into a single new one.
  • 57git: it is in .gitignore but git still tracks it. How do I fix it?Ignore rules only gate untracked files: git rm --cached untracks a committed file while keeping it on disk.
  • 58git: rename a branch locally and on the remoteThree moves: branch -m renames locally, push -u publishes the new name, push --delete retires the old one.
  • 59git: "fatal: tag 'v1.0' already exists" - move a tagTags are immutable markers: delete and re-tag, then push --force - and warn anyone who fetched the old tag.
