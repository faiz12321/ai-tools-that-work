Short answer

Common mistakes

  1. Trusting a folder called backup. Apply verifies root binding, exact selected names, backup digests and unchanged source bytes before its first write. An empty or stale backup is not enough.
  2. Overwriting later edits during undo. Undo first checks all files. Any bytes outside the original/planned states stop the restore. Stop other software from editing the tree during the operation.
  3. Calling a multi-file operation atomic. Writes can fail part way through. A journal saved first permits a limited mixed-before/after recovery. Do not delete backups or journals.
  4. Confusing byte restore with metadata restore. Timestamps, permissions, ownership and other file metadata are not backed up or restored. Use this only on fictional practice files.

Frequently asked questions

Does undo always guarantee no loss?

No. It refuses unexpected current bytes before restore, and keeps backup/journal copies. Concurrent or hostile changes and storage failure are outside its guarantees. The test suite includes an injected second-write failure and recovery for that fixture only.

What happens to a backup after undo?

It stays beside the root as notes.fr-backup, with the journal and a restored marker. The tool does not delete it or reuse it for another apply. Keep it; practise again in a different new empty lesson folder.

Which files are selected?

Only .txt files, including nested and hidden ones, under the chosen root. Non-.txt contents are untouched. Any encountered link/reparse point is refused, even on an ignored file or directory. Hard-linked files, special entries and case-colliding selected names are refused.

Does it preserve encoding and newlines?

For supported UTF-8 text, ordinary single-line replacement retains existing newline bytes and a BOM. The BOM is decoded as a character: do not target that marker itself. Invalid UTF-8 and NUL text are refused. Undo restores original bytes, not metadata.

Why a byte diff rather than line diff?

Normalizing newlines can hide real changes. This diff compares SHA256 digests and reports which selected files changed; preview shows matching lines.

What do the fixture checks prove?

They compare all three known practice names and SHA256 digests after undo, not just one count or one file. The tests exercise limited adversarial cases. Neither is a general real-data validator or malware sandbox.

Before you practise

Install PowerShell 7.4 or later separately and run these commands inside PowerShell (pwsh), not Command Prompt or Windows PowerShell 5.1. Ubuntu also needs /usr/bin/test (coreutils), used to reject special files because PowerShell item metadata did not reliably identify a named pipe in the adversarial check. No external package is downloaded by the lesson. Select 1 to 1000 .txt files, at most 1 MiB each and 10 MiB total, in a tree of at most 2000 entries. UTF-8 with or without BOM is supported; invalid UTF-8 and NUL content are refused. Matching is literal, case-sensitive and single-line, not regex. Reports/journals expose text and paths; keep private output private. Local processing does not control cloud sync or other software.
