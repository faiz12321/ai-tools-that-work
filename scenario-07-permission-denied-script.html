bash: ./script.sh: Permission denied. How do I fix it?

Short answer

Permission denied on a script you own usually means the file is not marked as runnable. Check it with ls -l script.sh. If the first column has no x, such as -rw-r--r--, add it with chmod +x script.sh and run ./script.sh again. It changes only that one file. Avoid chmod 777 and sudo as a first move.

Common mistakes with Permission denied

  1. Using chmod 777 because it works. It also lets everyone change the file. Add only the permission you need.
  2. Using sudo to get around Permission denied. The cause is still there, and the script now runs with full rights.
  3. Reading the file name as the problem. The message names the file you tried to run. The cause is its permissions, not its name.
  4. Not looking at ls -l first. One line shows what is missing. Look before you change anything.
  5. Forgetting ./ Typing backup.sh without ./ usually makes the shell search only the system paths, so you get command not found instead.

Frequently asked questions

What does Permission denied mean when I run a script?

The system will not let you do what you asked with that file. For ./script.sh it very often means the file is not marked as executable. ls -l shows whether it is.

What does exit status 126 mean?

In bash, 126 means the command was found but could not be run, often because of a missing execute permission. 127 means the command was not found.

Is chmod 777 a good fix?

It gives everyone on the machine permission to read, change and run the file. Usually, adding only +x is enough. You can limit it to the owner with chmod u+x.

Can I run the script without changing its permissions?

Often yes: you can pass the file to the shell, for example bash backup.sh. That was not part of this recording.

Do I need sudo?

Not for this problem. You own the file, so you can change its permissions yourself. Only use sudo when you understand what the script will do with those rights.

What if chmod +x does not fix it?

Check the first line of the script, check that the folder it is in allows programs to run, and check you have access to every folder on the path.
