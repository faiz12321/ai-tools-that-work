git: how do I undo a commit without rewriting history? (git revert)

Short answer

git revert <commit> adds a new commit that applies the opposite change, cancelling the old one. Nothing is deleted, so it is the undo that is safe even when the commit is already shared. git reset erases instead - fine only for private, unpushed work.

Safety: git revert never deletes commits - it only adds. The dangerous cousins are the rewriting commands: git reset --hard abandons commits, and interactive rebase rewrites them. Both are off-limits on anything shared. This lab has no remote; before reverting on a real shared branch, confirm you are undoing the right commit.

Common mistakes with git revert

  1. Reaching for reset on a shared branch. git reset --hard HEAD~1 makes the commit vanish locally, but everyone who pulled it still has it. The next push needs --force and strands their work. If it might be shared, revert.
  2. Expecting the bad commit to disappear. It stays in the log on purpose. The new Revert commit on top is the fix; the pair documents what happened and when it was undone.
  3. Reverting a merge commit blindly. A merge has two parents, so git needs -m 1 to know which side to keep. Plain git revert <merge> stops with an error. That case is beyond this lesson.
  4. Panicking at a revert conflict. If later commits touched the same lines, git pauses mid-revert. Resolve the conflicted files, git add them, then git revert --continue - or back out fully with git revert --abort.

Frequently asked questions

How do I undo a commit that might be shared?

Run git revert <commit>. git creates a new commit that applies the opposite change, cancelling the old one. Nothing is deleted, so anyone who already pulled the old commit stays in sync.

What is the difference between git revert and git reset?

git reset moves the branch backwards and abandons commits, rewriting history. git revert adds a new commit that undoes the change, keeping history honest. Reset is for private, unpushed work; revert is the safe undo once anything is shared.

Why does the reverted commit still show in git log?

Revert does not remove anything. The bad commit stays in history, and a new Revert commit on top cancels its effect. The pair documents what happened and when it was undone.

What does git revert --no-edit do?

It accepts git's default revert message, Revert "original message", without opening an editor. Without it, git opens your editor so you can adjust the message.

Can revert cause a conflict?

Yes. If later commits changed the same lines, git asks you to resolve the conflict, then run git revert --continue (or --abort to back out). Reverting the most recent commit is usually conflict-free.

How do I undo a revert?

Revert the revert: git revert <revert-commit> re-applies the original change as yet another new commit. History keeps the full story.
