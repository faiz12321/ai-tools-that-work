git: your local changes would be overwritten by checkout. How do I fix it?

Short answer

The error is git protecting your unsaved work: the branch you are switching to has a different version of a file you edited. Three doors: git stash push -m "note" to park the draft and get it back with git stash pop; git commit if the work is a real milestone; or git restore <file> if it is genuinely garbage. After any of the three, the switch works. And if git switches anyway with a modified file, that file is identical on both branches - your edit just rides along.

Common mistakes with this error

  1. Panic-discarding with git restore or checkout -- . The error feels like an emergency and the discard door is one short command - the classic way people lose an hour of real work. Look at git status and git diff first; discard only what you know is garbage.
  2. Committing the draft on the wrong branch just to unblock the switch. The switch works, but now a half-finished wip commit sits in permanent history on the wrong branch - you need squash surgery (lesson 44) or commit-moving surgery (lesson 43) to clean up. Stash takes five seconds and leaves no trace.
  3. Reading the error as 'the branch is broken or protected.' It names YOUR local changes as the reason. Branch protection is a server-side concept about pushing and merging; this refusal is local git refusing to overwrite your unsaved work.
  4. Forgetting parked stashes. The draft is safe on a hidden ref - and easy to forget. git stash list shows what is parked; pop it when you return, or it quietly becomes next month's mystery entry.

Frequently asked questions

How do I fix 'Your local changes to the following files would be overwritten by checkout'?

Pick one of three doors: git stash push -m "note" to park the draft and restore it later with git stash pop; git add + git commit if the work is a real milestone; or git restore <file> if the change is genuinely garbage. After any of the three, git switch works.

Why does git sometimes carry my uncommitted changes to the other branch?

Because the file you edited is identical on both branches. The switch never touches it, so the edit rides along and can be committed on either branch. Git only refuses when the checkout would actually overwrite unsaved changes - the protection is per-file, not repo-wide.

Does git stash lose my changes?

No. A stash is a real commit on a hidden ref. git stash push saves it, git stash pop applies it back and drops the entry, and git stash list shows everything parked. Stashes survive crashes and reboots.

What if I already committed on the wrong branch just to switch?

The commit can be moved: create the right branch at that commit, then reset the wrong branch back. That rescue is covered by the lesson on moving commits to a new branch. To avoid needing it, stash instead of committing when the work is unfinished.

The error appears but git status shows no changes. Why?

Usually invisible differences: file permission or mode changes, line-ending normalization (CRLF vs LF), or a file marked --assume-unchanged. git diff shows content changes; checking core.fileMode helps for the rest.
