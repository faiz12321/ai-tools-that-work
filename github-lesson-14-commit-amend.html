git: how do I fix the last commit? (git commit --amend)

Short answer

git commit --amend -m 'new message' replaces the last commit with a corrected one. Stage a forgotten file first and use --amend --no-edit to fold it in. Either way the commit gets a new hash, so do this only on commits nobody else has - never after a push.

Safety: --amend rewrites the last commit: the old hash is abandoned. Safe on local, unpushed work. On a pushed or shared commit it strands anyone who pulled the old one, and fixing that means a force-push. Never amend public history.

Common mistakes with --amend

  1. Amending a pushed commit. The old hash is what your teammates have. Replacing it forces a force-push and breaks their work. Amend is for local commits only.
  2. Making a second commit to fix a typo. 'fix typo' commits clutter history forever. Amend rewrites the last commit cleanly, before anyone sees it.
  3. Being surprised the hash changed. That is the mechanism, not a bug: amend creates a replacement commit. The old hash simply stops being on the branch.
  4. Trying to amend an older commit. Plain amend only touches the most recent one. Older fixes are interactive rebase territory.
  5. Panicking after a wrong amend. The old commit lingers in the reflog for a while; git reflog finds the old hash and you can reset back.

Frequently asked questions

How do I fix the last commit message?

Run git commit --amend -m 'new message'. git replaces the last commit with a corrected one. The commit gets a new hash because it is a new commit, not an edit of the old one.

How do I add a forgotten file to the last commit?

Stage the file with git add, then run git commit --amend --no-edit. The last commit is rebuilt with the file included and the message unchanged.

Why did the commit hash change after amend?

Amend does not edit a commit; it creates a replacement commit with a new hash and moves the branch to it. The old commit is left behind.

When must I NOT amend?

Never amend a commit you have pushed or shared. Other people may have built on the old hash; replacing it strands their work and forces an ugly force-push.

Can amend fix an older commit, not the last one?

No, plain amend only touches the most recent commit. Older commits need interactive rebase, which is a bigger tool for another lesson.

What if I amend by mistake?

The old commit still exists for a while and the reflog knows it: git reflog shows where the branch pointed, and you can reset back to the old hash.
