git: error: pathspec did not match. How do I fix it?

Short answer

The name you gave git does not exist as a branch, tag or file. Run git branch to see the real names. If you meant an existing branch, fix the typo (and if it lives only on the remote, run git fetch first). If you meant a new branch, create it: git switch -c name.

The situation

Common mistakes with pathspec errors

  1. Retrying the same command louder. The name does not exist; running it again changes nothing. List what exists with git branch, then act.
  2. Assuming checkout creates branches. Plain git checkout docs only switches. Creation needs git switch -c docs (or the older git checkout -b docs).
  3. Forgetting the remote case. A branch that exists only on the server is invisible to local checkout until you git fetch. This lab is local-only; on a real clone, fetch first.
  4. Grabbing -f to silence the error. Force flags discard uncommitted work. A pathspec error needs a correct name, not more force.
  5. Mixing up branches and files. checkout accepts both, which is why the message mentions files. git switch handles branches and git restore handles files, one meaning each.

Frequently asked questions

What is a pathspec?

A pathspec is how you name things to git: a branch, a tag, a commit, or a file path. Commands like checkout and restore read the word you give them as one of these.

Why does git say 'did not match any file(s) known to git'?

Because nothing with that name exists in the repository: no branch, no tag, and no tracked file at that path. git checked every kind of thing the word could mean and found none.

I wanted a new branch. What is the fix?

Create it: git switch -c docs. Plain git checkout docs only switches to things that already exist; it never creates a branch.

I wanted an existing branch. What went wrong?

Usually a typo, or the branch exists only on the remote. Run git branch to list local branches and git branch -r for remote ones, then switch to the exact name.

Does the error change anything?

No. The command failed before touching anything: HEAD, your files and the staging area are exactly as they were. You are free to retry with the right name.

How do I avoid this error?

List before you switch: git branch shows what exists. Use git switch for branches and git restore for files, so each command has one clear meaning.
