git: "error: src refspec main does not match any" on push

Short answer

The name after origin matches nothing on YOUR side. The usual cause on a new project: you staged files but never committed, so the branch ref does not exist yet - make the first commit and the same push works. The other cause: a typo, or your branch is really called master while you typed main. git branch --show-current settles it in one word.

Common mistakes with src refspec errors

  1. Reading it as a remote or login failure. "src" is your side: git could not find the local ref you named. The remote was never asked. Auth failures say "Permission denied"; network failures say "Could not resolve host".
  2. Re-running the same push hoping it passes. Nothing changed between runs, so nothing changes in the result. The fix is creating the ref (first commit) or correcting the name - never repetition.
  3. Staging but never committing. git add alone does not create a branch. A branch ref is a bookmark on a commit; with zero commits there is nothing to bookmark, and the push has nothing to read.
  4. Reaching for git push --force. Force cannot push a ref that does not exist, and on real shared work it is the dangerous button. This error never needs force - it needs a commit or the right name.

Frequently asked questions

What does "error: src refspec main does not match any" mean?

src is your side. Git looked for a local ref named main to push and found nothing. Two common causes: the branch has no commits yet (a branch ref is born with its first commit), or the name you typed is not the branch's real name (a typo, or master vs main).

How do I fix it on a brand-new repository?

Make the first commit, then push again: git commit -m "your message" followed by the same git push -u origin main. Staging files with git add is not enough - the branch ref exists only once it points at a commit.

Why do I get it when I already have commits?

Then the name matches no local branch: a typo (origin man), or your branch is really called master while you typed main. Check with git branch --show-current, then either push the real name or rename once with git branch -m master main.

Is "error: failed to push some refs" a sign of data loss?

No. It means nothing was sent. The remote is untouched, your files and commits are untouched, and the same push works once the local ref exists.

How is this different from "no upstream branch"?

No upstream branch means your local branch exists and has commits, but git does not know which remote branch to pair it with - fixed once with git push -u. src refspec does not match any means the local ref you named does not exist at all: no commits yet, or a wrong name.
