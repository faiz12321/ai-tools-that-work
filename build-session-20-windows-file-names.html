How to check file names against Windows naming rules

Short answer

Some file names that work elsewhere are not allowed on Windows: a colon, a question mark, a name like NUL, or a name that ends in a period. This lesson builds a small read-only Python tool that checks a list of names, or the names inside a folder, against the rules on Microsoft's naming page and prints the ones that break them. The tool has no code that renames or creates a file. A clean report does not mean every program will accept a name.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Checking only the characters. The first version in this lesson looks only for the forbidden characters. It misses a reserved name like NUL.txt and a name that ends in a period.
  2. Thinking NUL.txt is fine because it has an extension. Microsoft's page says a reserved device name followed by an extension is still treated as the device name.
  3. Ending a name with a space or a period. The page says not to. The file system may store such a name, but the Windows shell and user interface do not handle it well.
  4. Treating a clean report as a guarantee. The tool knows only the rules on one page. A program or file system can have more.

Frequently asked questions

How do I check a file name for Windows problems?

Compare it with the rules on Microsoft's naming page: forbidden characters, reserved device names, and a name ending in a space or a period. This lesson builds a small tool that does that.

Will this rename or delete my files?

No. The tool only reads names. Tests check that nothing is created or changed in the practice folder.

Why are the bad practice names only in a list?

Windows can refuse to create a file called NUL or one with a colon in its name, so the lesson keeps them as text. The folder practice uses only ordinary names.

Why is a long path only a warning?

The older limit is 260 characters for a whole path. Since Windows 10 version 1607 the limit can be turned off, so a long path is not always an error.

Does a clean report mean the name is safe everywhere?

No. It means the name passed the rules the tool knows. Other programs and file systems can have more rules.

Why are some names printed with backslash codes?

Special characters are written as escapes so the report shows on any console. For example a small superscript 1 is written as \xb9.
