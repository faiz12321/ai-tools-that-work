git: how do I mark a release point? (git tag)

Short answer

git tag -a v1.0 -m 'message' marks the current commit as a release: an annotated tag with your message, name and date. Add a hash to tag an older commit. A plain git tag name is a lightweight marker - just a name, no message. Tags never move; branches do.

Safety: tags are gentle - creating one changes no files and moves no branch. The hazards to name: git tag -d deletes a tag, and reusing a tag name others already fetched rewrites a promise. Never move a shared tag; mint a new name instead. This lab has no remote, and no push is shown.

Common mistakes with tags

  1. Tagging HEAD when the release was an older commit. The tag pins wherever you point it. Find the real release hash in the log first, then tag that hash.
  2. Using a lightweight tag for a real release. A bare name carries no message, tagger or date. Releases deserve -a; lightweight tags are for private scratch markers.
  3. Expecting tags to travel like branches. They stay put. New commits never move a tag - that immobility is exactly why releases use them.
  4. Retagging after the tag is shared. Deleting and recreating a fetched tag leaves everyone else pointing at the old one. If the name is out, choose a new name (v1.0.1) rather than moving v1.0.

Frequently asked questions

How do I tag a release in git?

Run git tag -a v1.0 -m 'message' on the release commit, or git tag -a v1.0 <hash> -m 'message' to tag an older commit. The -a makes an annotated tag: a real object with your message, tagger and date.

What is the difference between an annotated and a lightweight tag?

An annotated tag (-a) is its own object storing message, tagger and date - the right choice for releases. A lightweight tag is only a name pointing at a commit, fine for scratch markers. git show displays the difference clearly.

Can I tag a commit from the past?

Yes. Find the hash with git log, then git tag -a v1.0 <hash> -m 'message'. The tag points at that commit no matter where the branch has moved since.

How do I list and inspect tags?

git tag lists all tag names. git show <tag> displays the tag message (for annotated tags) and the commit it points at.

Do tags move when I commit more work?

No. A tag stays pinned to its commit forever. That is the point: branches move, tags mark fixed moments like releases.

How do I fix a wrong tag?

Delete it locally with git tag -d <name> and create it again at the right commit. If the tag was already shared, retagging confuses everyone who fetched it - prefer a new tag name instead.
