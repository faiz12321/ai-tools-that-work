Why does a website open on other PCs but not on mine? Check the hosts file

Short answer

Windows looks at its hosts file before it asks DNS. A leftover line there can send one name to the wrong address on your PC only. Read it with Get-Content $hosts | Select-String demo-shop.test (use your own site name). If ping finds an address but nslookup says the name does not exist, a hosts line is a likely source of that address. Back up the file, remove only the wrong line, then run ipconfig /flushdns.

Common mistakes with the hosts file

  1. Reading a ping timeout as a DNS problem. A timeout means nothing replied at the address. Check where the address came from.
  2. Trusting only one tool. ping and a browser use the hosts file. nslookup does not. When they disagree, a hosts line is a likely cause.
  3. Editing the hosts file without a backup. Copy the file first, then change one line, then flush the cache and test.
  4. Deleting the whole file. It may hold other lines you need. Remove only the line you understand.
  5. Forgetting the DNS cache. Windows remembers answers. Run ipconfig /flushdns after a change before you test again.

Frequently asked questions

Why does one PC open a site and another does not?

Windows checks its cache, then the hosts file, then DNS. A line in the hosts file overrides DNS on that one PC only, so other computers still get the right answer.

Where is the hosts file?

C:\Windows\System32\drivers\etc\hosts on Windows. It is a plain text file. Editing it needs an administrator window.

Is it safe to edit the hosts file?

It is a system file. A wrong line can send a site to the wrong place. Read it first, back it up before any change, and remove only a line you can explain.

Does nslookup use the hosts file?

No. nslookup asks a DNS server directly, so it can disagree with ping and your browser when a hosts line exists.

Does Resolve-DnsName use the hosts file?

By default it can, as Microsoft's DNS troubleshooting page shows. With -DnsOnly in the recording on this page it asked only DNS.

What if I cannot work out which line is wrong?

Microsoft documents resetting the hosts file to its default. That is a bigger step, so save a copy of your current file first.
