bash: cd: too many arguments. How do I fix it?

Short answer

bash splits what you type at the spaces, so cd My Documents reaches cd as two words. Put the name in quotes: cd "My Documents", or escape the space: cd My\ Documents. Tab completion writes the escaped name for you. Then check where you are with pwd.

Common mistakes with spaces in names

  1. Renaming the folder to remove the space. It works, but everything pointing at the old name breaks. Quoting changes nothing on disk.
  2. Retyping the same command. The shell splits on spaces every time, however carefully you type.
  3. Assuming the folder is missing. too many arguments is about word count, not existence. No such file or directory is the missing-folder message.
  4. Forgetting that every command splits on spaces. ls My Documents looks for two things, My and Documents. Quote anywhere a name has a space.
  5. Quoting only part of the name. cd "My"Documents becomes one wrong name, MyDocuments. The whole name goes inside the quotes.

Frequently asked questions

Why does cd say too many arguments?

bash splits what you type at the spaces, so cd My Documents arrives as cd with two words, My and Documents. cd takes at most one folder name, so two words is one too many.

Quote or backslash?

cd "My Documents", cd 'My Documents' and cd My\ Documents all work. Pressing Tab after part of the name lets the shell finish and escape it for you.

Does the space break other commands too?

Yes. ls My Documents looks for two things, and rm with an unquoted spaced name can remove the wrong files. Quote wherever a name has a space.

Why did cd print nothing?

cd is quiet when it moves. pwd prints where you are, so you can check instead of guessing.

What exit status does a failed cd give?

1 here, and scripts see that number. 0 means the move happened. Check with echo $? right after the command.

What about a folder with quote marks in its name?

Use the other quote style around the name: cd "it's" or cd 'say "hi"'.
