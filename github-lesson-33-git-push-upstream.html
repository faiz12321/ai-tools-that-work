git: "no upstream branch" on push (git push --set-upstream)

Short answer

Git will not guess where a new branch belongs. Push it once with git push --set-upstream origin your-branch (same as -u): that sends the branch AND records the tracking link, so plain git push and git pull work from then on. Check the wiring any time with git branch -vv.

Common mistakes with upstream tracking

  1. Re-typing the full push every time. git push origin feature/login works without -u, but you will type it forever. One --set-upstream and the branch is wired for bare git push and git pull.
  2. Thinking the error means the push partially happened. It is a refusal, not a failure midway: nothing was sent. The branch appears on the remote only after a successful push.
  3. Setting upstream to the wrong branch. -u records exactly what you name: git push -u origin main from a feature branch ties it to main. Name the matching branch, then confirm with git branch -vv.
  4. Confusing the two -u effects. The push half happens once; the tracking half is permanent config. Forgetting which you did leads to "why does git pull work on main but not here?"

Frequently asked questions

What does "fatal: The current branch has no upstream branch" mean?

Your local branch has no tracking link to any remote branch, so plain git push has no idea where to send it. Git refuses to guess. The fix is printed in the error: git push --set-upstream origin your-branch-name.

How do I fix the no upstream branch error?

Run git push --set-upstream origin your-branch-name (or the shorter git push -u origin your-branch-name). This pushes the branch AND records the tracking link, so future git push and git pull work with no arguments.

What does git push --set-upstream (or -u) actually do?

Two things: it pushes the branch to the named remote, and it records "this local branch tracks that remote branch" in your repo config. That tracking link is what makes bare git push and git pull work, and what powers the ahead/behind counts in git status and git branch -vv.

Why did main push fine but my new branch fail?

Your main branch already had a tracking link (set at clone time or by an earlier push -u). A branch you create locally with git switch -c or git branch has none until the first push --set-upstream.

How do I see which branches track which remotes?

git branch -vv lists each local branch with its tracked remote branch in brackets, like * main 7b1b376 [origin/main] step 1. git status also shows "Your branch is up to date with 'origin/main'" when tracking is set.
