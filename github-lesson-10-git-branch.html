git: how do I create, switch, and delete branches?

Short answer

git branch name creates a branch on your current commit, git switch name moves you to it, and git branch -d name deletes it - but only after git checks its commits live somewhere else. git branch -D name skips that check, so use it only when you are sure.

Safety: git branch -D deletes a branch even when its commits exist nowhere else; the printed hash is a last-chance recovery clue, not a backup. git reset --hard is a different destructive command and is not a way to delete branches.

Common mistakes with branches

  1. Creating the branch but working on the old one. git branch feature only makes the label. Until git switch feature runs, commits still land on main.
  2. Reaching for -D because -d refused. The refusal is information: that branch holds commits nothing else has. Look at them first; force only when you mean it.
  3. Deleting the branch you are standing on. git refuses that too, but the fix is to switch away first, not to find a way around it.
  4. Trying to delete branches with reset --hard or by removing files. Branches are labels on commits. File edits and resets do not remove them; git branch -d does.
  5. Hoarding dead branches. A branch you will never touch again is clutter that slows every list and lookup. Merge it or delete it.

Frequently asked questions

How do I create a branch in git?

Run git branch branch-name. The new branch points at your current commit. Nothing switches yet; you are still on the old branch until you run git switch branch-name.

How do I see my branches?

Run git branch with no arguments. It lists every local branch and marks the one you are on with a star.

How do I delete a branch?

Run git branch -d branch-name. git checks the branch is fully merged first and refuses if deleting it would strand commits. git branch -D skips that check and deletes anyway.

What is the difference between -d and -D?

-d is the safe delete: it only works when the branch's commits are reachable from elsewhere, so nothing is lost. -D is the force delete: it removes the branch even when its commits exist nowhere else.

Can I recover a deleted branch?

Sometimes. The delete message prints the branch's last commit hash, and the commit may still be reachable through the reflog for a while. Treat recovery as a lucky escape, not a plan: do not force-delete work you might need.

Does switching branches change my files?

Yes. git switch updates your working files to match the branch you move to. Commit or stash uncommitted work first so nothing blocks the switch or gets carried across by accident.
