git: what is "origin"? (git remote -v)

Short answer

"origin" is not a git keyword - it is the default nickname for the repository you cloned from. git remote -v lists each remote's fetch and push URLs, git remote show origin describes the whole relationship, and git remote rename proves the name is just a label you control.

The situation
You cloned a repo and every command says "origin": push origin, fetch origin, origin/main. What IS origin - a place, a branch, a keyword? Until that word is demystified, every sync command feels like incantation.

Common mistakes about origin

  1. Thinking "origin" is a keyword. It is a default nickname chosen at clone time. git push origin main means "push to the remote nicknamed origin" - rename it and the same command needs the new name.
  2. Thinking origin is a branch. origin is the remote; main is a branch; origin/main is your local note of where the remote's main was at last sync. Three different things that share two words.
  3. Assuming a remote must be a server. A remote is any reachable repository - GitHub, a company host, or a folder path on the same machine, like this lab's bare repo.
  4. Guessing the URL instead of asking. git remote -v prints exactly where fetch and push go. One second of looking beats a wrong assumption pushed to the wrong place.

Frequently asked questions

What does "origin" mean in git?

Origin is just the default nickname git gives the remote repository you cloned from. It is a name, not a keyword: commands like git push origin main mean "push to the remote nicknamed origin". You can rename it or add more remotes with other names.

What does git remote -v show?

One line per remote and direction: the nickname, the URL, and whether it is used for fetch or push. A typical clone shows origin twice - once with (fetch), once with (push) - usually the same URL.

Does a git remote have to be on the internet?

No. A remote is any repository git can reach: a GitHub URL, a company server, or a plain folder path on the same machine. A local bare repository at a file path works as a remote for clone, fetch and push.

How do I rename a git remote?

git remote rename origin upstream renames the nickname. All tracking configuration follows the new name; run git remote -v before and after to see only the label change.

How do I see what a push will send, and to where?

git remote show origin lists the fetch and push URLs and which local branch pushes to which remote branch. The push itself prints the range of commits moved, like b43fd2b..838e25d main -> main.
