git: how do I undo the last commit?

Short answer

To remove the last commit but keep its changes in your files, run git reset --soft HEAD~1. The commit leaves the branch and its changes come back as staged edits. Use --mixed (the default) to also unstage them. Avoid --hard: it throws the changes away together with the commit. If you already pushed the commit, use git revert instead.

Common mistakes when undoing commits

  1. Reaching for --hard when you meant --soft. --hard deletes the commit's changes from your files too. If that text mattered, it is gone. Pick the reset that matches what you want to keep.
  2. Resetting a commit you already pushed. That rewrites shared history and breaks teammates' pulls. For public commits, git revert adds a new commit that undoes the old one without rewriting anything.
  3. Reading silence as success or as failure. git reset --soft printed nothing in this recording. Quiet is just quiet; check git status and git log to see what actually happened.
  4. Typing HEAD~1 without looking. HEAD~1 means one commit before the current top. Run git log --oneline first and count from the real top, not from memory.
  5. Deleting the whole repository in a panic. Undoing one commit is a single reset command; the rest of your history is untouched.

Frequently asked questions

What does git reset --soft HEAD~1 do?

It removes the last commit from the branch and keeps that commit's changes staged, ready to edit or commit again. Nothing in your files is lost.

What is the difference between --soft, --mixed and --hard?

All three move the branch back. --soft keeps the changes staged, --mixed (the default) keeps the changes in your files but unstages them, and --hard throws the changes away together with the commit.

What does HEAD~1 mean?

One commit before the current HEAD. HEAD~2 is two commits before, and so on. Count from the top of git log, not from memory.

Is it safe to reset a commit I already pushed?

No. Resetting rewrites history that others may have pulled, which breaks their work. For commits that are already public, use git revert instead; it adds a new commit that undoes the old one.

Can I get an undone commit back?

Yes, for a while. git reflog remembers where HEAD pointed, so you can reset the branch back to the old commit's hash until garbage collection removes it.

git reset --soft printed nothing. Did it work?

Silence alone proves nothing either way. Verify with git status and git log: the commit should be gone from the log and its changes should appear as staged edits.
