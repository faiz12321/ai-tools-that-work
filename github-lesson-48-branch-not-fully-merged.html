git: error "the branch is not fully merged" - how do I delete it?

Short answer

The refusal is protection, not failure: git branch -d only deletes when every commit on the branch is reachable from elsewhere. See what is at risk with git log --oneline main..branch-name. If the work is wanted, git merge branch-name first, then -d passes. If it is truly abandoned, use git branch -D branch-name and keep the hash it prints (Deleted branch x (was abc1234)): the commit stays in the object store and git switch -c name abc1234 brings it back.

Common mistakes with 'not fully merged'

  1. Reaching for -D reflexively. The refusal message names -D, so people type it before reading what would be lost. One git log --oneline main..branch-name shows the exact commits; decide after seeing them, not before.
  2. Merging junk into main to satisfy -d. Merging a failed experiment just so the safe delete passes ships the bad code AND falsifies the history. Finished work gets merge-then--d; abandoned work gets -D. Never the reverse.
  3. Assuming pushed means merged. A branch can be fully pushed and still unmerged - the -d check is about local reachability, not the remote. Conversely a never-pushed branch that main has merged deletes cleanly.
  4. Ignoring the '(was abc1234)' line. That hash is the recovery key. After any -D, note it (or know git reflog can find it) before the shell scrolls away - unreferenced commits survive only until garbage collection.

Frequently asked questions

What does 'error: the branch is not fully merged' mean?

git branch -d is the safe delete: it checks that every commit on the branch is reachable from another branch. The error means some commits exist only under this label, so deleting would orphan them. See exactly which with git log --oneline main..branch-name.

How do I fix it and delete the branch?

Wanted work: git merge branch-name, then git branch -d branch-name passes. Abandoned work: git branch -D branch-name, the explicit override. Do not merge bad work into main just to make the safe delete pass.

What is the difference between git branch -d and -D?

-d refuses when commits would be orphaned; -D deletes without checking. Use -d for everyday pruning and -D only for work you have decided to abandon - and keep the '(was <hash>)' line it prints.

Can I recover a branch deleted with -D?

Usually yes, before garbage collection. Only the label is deleted; the commits stay in the object store. Run git switch -c new-name abc1234 with the hash from the delete output (or find it via git reflog) and the work is back under the new name.

How do I list branches that are not fully merged?

git branch --no-merged main lists branches with commits missing from main - exactly the ones -d would refuse. The mirror, git branch --merged main, lists branches safe to -d right now.
