git: fetch vs pull - what is the difference?

Short answer

git fetch downloads the new commits and updates origin/main - your local snapshot of the remote - without touching your files or your branch. git pull is fetch plus merge: it also lands those commits in your current branch. The safe habit: fetch first, look with git status and git log HEAD..origin/main, then pull.

Safety: git fetch never touches your working tree - it is always safe. git pull merges into your current branch, and when both sides moved it can create a merge commit or stop on conflicts; the fetch-then-look habit is how you avoid surprises. Nothing here rewrites history or deletes anything.

Common mistakes with fetch and pull

  1. Thinking fetch updates your files. It only refreshes origin/main and friends. After a fetch, your branch and files are exactly as they were - which is the point: you get to look first.
  2. Pulling blind. Pull merges immediately. If both sides moved, you land in a merge you have not seen. Fetch, read git status and the incoming log, then pull.
  3. Mixing up main and origin/main. main is your branch; origin/main is a bookmark of the remote's state at your last fetch. Between fetches they can point at different commits, and status compares them for you.
  4. Being surprised by a merge commit. A behind-only pull fast-forwards. A diverged pull must join two lines of history, creating a merge commit (or rebasing, if configured). That is normal - but know which case you are in before pulling.

Frequently asked questions

What is the difference between git pull and git fetch?

git fetch downloads new commits and updates the tracking branches (origin/main) only - your working tree and your branch are untouched. git pull is git fetch followed by git merge origin/main (or a rebase, if configured): it also lands the changes in your current branch.

Does git fetch change my files?

No. Fetch writes only to the remote-tracking refs like origin/main. Your working tree and current branch stay exactly as they were, which is why fetch is always safe to run.

How do I see what git pull would bring in?

Run git fetch, then git log --oneline HEAD..origin/main to list the incoming commits, or git diff HEAD..origin/main for the actual changes. After a fetch, git status also tells you how many commits behind you are.

Is origin/main the same as my main branch?

No. origin/main is your local snapshot of the remote's main at your last fetch. main is your own branch. They move independently between fetches.

When does git pull create a merge commit?

When your branch and the remote have both moved since your last common commit (diverged), pull must join them: a merge commit by default, or a rebase if pull.rebase is set. When you simply fell behind, pull fast-forwards with no merge commit.
